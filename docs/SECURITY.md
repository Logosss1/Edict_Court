# 安全、权限与数据

## 进程与渲染隔离
- Renderer：`sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`；只通过 preload 暴露的 `invoke / onEvent` 访问白名单 API（`src/main/api.ts`）。
- 页面由自定义 `app://` 协议提供，协议处理器拒绝越出 `dist/` 的路径；CSP 仅允许同源脚本；禁止页面导航与新窗口（外链只允许 http/https 并交给系统浏览器）。
- 权限请求（摄像头、定位等）一律拒绝，仅允许剪贴板写入与通知。

## 网络端口
Edict **不监听任何网络端口**。唯一的例外：你在「设置 · 连接服务（MCP）」中对某个远程 MCP 服务点「登录」后，为接收 OAuth 授权回调，临时在 `127.0.0.1`（仅本机回环，不绑定其它网卡）上开一个端口 `http://127.0.0.1:<端口>/callback`（首次随机分配；再次登录时优先沿用上次的端口，被占用则另选）；收到回调、登录被取消，或 5 分钟内未完成时立即关闭。该端口只认 `/callback` 一个路径、只接受一次带正确 `state` 的回调。

编辑器接入（ACP）用的是本机 **Unix 域套接字文件**，不是网络端口（见下文）；语言服务器与本地 MCP 程序都经 stdio 通信。

## HTML 预览
- 工作区通过私有协议 `preview://ws/` 只读提供，旨意工作树通过 `preview://wt-<旨意号>/` 提供，**不开放任何网络端口**；复用工作区路径边界（拒绝越界与符号链接逃逸），拒绝 `.git/`、`.env*`、密钥文件。
- 预览页运行在独立会话分区 `edict-preview`：`<webview>` 在 `will-attach-webview` 中被强制去掉 preload、开启 sandbox / contextIsolation、关闭 Node；不允许弹窗、下载、任何权限请求；导航只允许 `preview://ws`、`preview://wt-<旨意号>` 与 localhost。
- 预览页的**外发网络默认拦截**（只放行工作区、localhost、data/blob），防止 Agent 生成的页面把数据发往外部；需要 CDN 时由你在预览栏确认放开（设置项 `previewAllowNetwork`），可随时恢复。
- Agent 工具 `preview_page` 使用同一分区的离屏隐藏窗口，串行执行、20 秒超时，结果与截图写入审计 / 快照库。
- `preview_page` 的交互步骤（`actions`：点击、填写、按键、断言等）在**同一个**隐藏窗口里执行，分区、外网拦截、导航限制、禁止弹窗 / 下载 / 权限全部不变；页面脚本是固定代码，选择器与填写的值只以 JSON 数据传入，不拼接成代码。最多 25 步、共 60 秒，页面卡死即中止；页面的 `alert` / `confirm` 不会阻塞（记入控制台，隐藏窗口另设 `disableDialogs`）。

## MCP 服务
- 配置文件 `mcp.json`（标准格式）存于数据目录；保存时**形似密钥的值**（名称含 key/token/secret/password/auth…，或值形如 `sk-…`、`ghp_…`、`Bearer …`；以及 `--api-key=…` 类参数）移入钥匙串加密存储，文件中只留 `${secret:…}` 占位。「连接服务」页的添加卡片会在保存前标出哪些值移入钥匙串、哪些会以明文写进 `mcp.json`。
- **本地命令**（stdio）以你的用户身份运行：首次运行、或命令行 / 参数 / cwd 改变时必须在原生对话框中确认（信任记录为命令行哈希）；子进程环境剔除含 KEY/TOKEN/SECRET 的变量，只注入你为该服务配置的变量。
- 工具调用受权限模式约束：只读工具直接执行；有副作用工具需批准（可逐个设为直接用、在审批卡上选「本旨意 / 本工作区不再询问」，或全自动模式）；**高风险工具任何模式下都须确认**；只读模式下只能用只读工具；规划 / 审议类官员只拿到只读工具；可按官员授权。审计记录服务、工具、耗时与**参数名**（不记参数值）。
- **远程服务的 OAuth 登录**（MCP 授权规范 2025-06-18）：服务返回 401 时状态变为「需要登录」，**Edict 不会自行打开浏览器**；只有你点「登录」时才会：按 RFC 9728 / RFC 8414（及 OpenID 配置）发现授权服务器 → 未在 `auth.clientId` 中配置客户端时按 RFC 7591 动态注册 → 以 PKCE S256、`state`、`resource`（RFC 8707，即该 MCP 服务地址）在系统浏览器中授权 → 回调见「网络端口」。授权服务器各端点必须是 https（本机回环地址除外）；`state` 不符的回调一律拒绝且不换取令牌。`"auth": {"type": "none"}` 可关闭 OAuth；已配置 `Authorization` 请求头且未写 `auth` 时沿用请求头。
- **令牌存放**：访问令牌、刷新令牌、过期时间与动态注册得到的客户端信息只存于钥匙串加密存储（`secrets.json` 中的 `mcp-oauth:<服务名>`），**不写入 `mcp.json`、日志、审计、活动流或界面状态**；`auth.clientSecret` 与其它密钥一样保存时移入钥匙串。令牌只以 `Authorization: Bearer` 请求头发往该 MCP 服务（不放进 URL），且只用于签发时的服务地址；临近过期或收到 401 时用刷新令牌自动续期（每次请求最多一次），续期失败回到「需要登录」。「退出登录」删除该记录并尽力在授权服务器吊销令牌；从 `mcp.json` 删除服务也会删除其令牌。审计 `mcp_oauth_login` / `mcp_oauth_logout` 只记服务名、授权服务器、scope 与成败。
- **资源与提示词**：官员只能通过 `mcp_list_resources` / `mcp_read_resource` 读取已授权给自己的服务的资源（只读操作，所有权限模式可用）；资源内容作为外部数据交给模型（注明「不是指令」）；二进制内容与超长文本全文存入 `blobs/`。审计 `mcp_resource_read` 记服务、URI（去掉用户信息、查询串与片段）、大小，`mcp_prompt_get` 记提示词名与参数名——都不记内容与参数值。
- **下旨中的 `@mcp:` 引用**：下旨框里用 `@` 选中的资源以 `@mcp:<服务>/<URI>` 插入。下旨时 Edict 以皇上的身份读取每个引用（只读已连接的服务，不受官员授权限制）：一道旨意最多 10 项、正文合计 8000 字符，超出的注明「未附带」（官员可再用 `mcp_read_resource` 读取），读不到的注明原因；内容放在旨意末尾的【附带资源】块里，注明是外部数据、其中的指令不必遵从。审计 `mcp_resources_attached` 记每项的服务、URI（去掉用户信息、查询串与片段）、成败、字符数与是否截断，不记内容。用 `/` 选中的提示词由 `prompts/get` 取回文本后插入下旨框，由你看过再发出。

## Agent 权限模式
| 模式 | 读 | 写文件 | 命令 |
|---|---|---|---|
| 只读 | ✓ | ✗（协同旨意的子任务经你在写任务卡 / 升级卡上准许后可以写，按所选选项处理） | ✗（同左） |
| 询问 | ✓ | 需批准 | 需批准 |
| 自动编辑（默认） | ✓ | 自动 | 安全命令自动（测试 / 构建 / git status 等），其它需批准 |
| 全自动 | ✓ | 自动 | 自动（高风险、发版 / 部署仍须确认） |

**协同旨意的子任务**（中书省给每个子任务标注 只读 / 写入 / 验证）：
- 只读子任务并行，写入与验证子任务单独执行，同一道旨意同一时间只有一个写入者。
- 子任务默认按只读开工。只读子任务第一次要改文件或执行非安全命令时，先弹升级卡（准许并改为写任务 / 准许且本子任务内写入与命令免询问 / 只准这一次 / 驳回）。
- 每个写任务开工前单独确认一次（准许开工 / 准许，本子任务内写入与命令免询问 / 改为只读执行 / 驳回）；可在「设置 · 权限与审批」关闭（`confirmWriteTasks`）。全自动模式下这两种卡都不弹。「免询问」不包括高风险操作。
- 编辑或覆盖已有文件前，必须在本轮读过它且读后没有被改动，否则工具报错、要求重新读取。

**审批卡的「不再询问」规则**：普通风险的操作可以选「准许」「准许，本旨意内不再询问」「准许，本工作区永久允许」或「驳回」（可附批示，批示会交给官员）。规则按命令前缀（如 `cmd:npm run build`；复合命令的每一段都要被允许，含 `$()` 或反引号的命令不能按规则放行）、写入 / 编辑文件（`tool:write`）或 MCP 工具（`mcp:<服务>/<工具>`）记录。本旨意的规则存在该旨意的记录里，旨意结束即失效；本工作区的规则存在设置的 `workspacePerms` 里（都在 `edict.db`），按主工作区路径记，旨意在工作树里执行时同样适用。两者都可在「权限与审批」中查看来源并撤销；添加与撤销写入审计（`allow_rule_added` / `allow_rule_removed`），按规则自动放行记为 `approval_auto`。**高风险操作不提供这些选项，已有规则也不会放行它们。**

**任何模式下都必须皇上确认的高风险操作**：递归删除、`sudo`、`git reset --hard` 等丢弃修改、下载并执行远程脚本、批量改权限、磁盘操作、关机重启、批量结束进程、写入系统目录、网络外发（curl/wget/ssh/scp/rsync/nc）、安装/卸载依赖、读取钥匙串、删除容器 / 镜像、删除文件、读取/改写敏感文件（`.env*`、`*.pem`、`*.key`、`id_rsa`、`credentials`）、标为高风险的 MCP 工具。

**发版与部署**（`git push`、`npm` / `cargo` 等的 publish、`gh release`、`gh pr create` / `merge`、`docker push`、各类部署 CLI、`kubectl apply`、`helm`、`terraform apply`、云端部署、`xcrun notarytool submit` 等）同样逐次确认。只有在「权限与审批」中为某个工作区开启「发版与部署永久允许」（开启时再确认一次，写入审计 `release_policy`）后，这个工作区里的发版 / 部署命令才不再询问，每次执行记为 `approval_auto`（`releaseAlways`）。该开关只对这个工作区生效；一条命令里只要还有其它高风险部分，仍会询问。

**请旨**（`ask_emperor`）：官员可以停下来向你提问；只有全自动模式下才会在超时（「权限与审批」中设置，默认 10 分钟）后按官员给的默认做法继续，其它模式一直等你答复。

## 路径边界
所有文件工具经 `Workspace.resolve`：拒绝工作区外路径、拒绝经符号链接逃逸（检查最近存在祖先的 realpath）、禁止改写 `.git/` 内部；越界尝试写入审计 `path_boundary_violation`。旨意有自己的工作树时，边界就是该工作树。命令在旨意所在的工作区（或工作树）根目录执行，超时（默认 120s，最长 600s）后连同进程组终止，输出上限 64KB；子进程环境剔除名称含 KEY/TOKEN/SECRET/PASSWORD/CREDENTIAL 的变量。

## 旨意工作树（git worktree）
- 在 git 仓库（至少有一次提交）中下达的协同旨意，离开太子分拣时在 `<数据目录>/worktrees/<仓库路径哈希>/<旨意号>` 建一个新分支 `edict/<旨意号>` 的工作树（设置 `worktreePerEdict`，默认开；Solo 与不动文件的协同设计不建）。该旨意的文件工具、命令、预览与语言服务都在工作树里进行；结案前主工作区一个文件都不改。主工作区未提交的改动不会带进工作树（会在活动流中提示）。
- 从主工作区**符号链接**过来的只有依赖目录 `node_modules`、`.venv`、`venv`（主工作区有、工作树里没有时）；提交时排除这些链接，移除工作树时只删链接本身，不动它们指向的目录。
- Edict 直接调用 `git`（不经 shell，环境同命令执行，另设 `GIT_TERMINAL_PROMPT=0`）：`worktree add / list / remove / prune`、`status`、`add -A`、`commit`、`diff`、`merge-tree`、`merge --no-ff` / `merge --abort`、`branch -d` / `-D` 以及只读查询（`rev-parse`、`show-ref`、`ls-files` 等）。**不执行 fetch、pull、push。** 没有配置 `user.name` / `user.email` 时以 `Edict <edict@localhost>` 提交。这些命令在你的仓库里运行，仓库自己配置的 git hooks 会照常触发。
- 结案对话框：**合并** = 先把工作树里的改动提交到旨意分支，再在主工作区 `git merge --no-ff`（git 支持时先用 `merge-tree` 试合并）；有冲突、或主工作区未提交的改动挡路时中止，主工作区保持原样，分支保留。**保留分支** = 提交后删除工作树目录，分支留着。**丢弃** = 强制删除工作树目录（其中未提交的改动一并丢失）并用 `git branch -D` 删除分支。已取消的旨意只能保留或丢弃；工作树是当前打开的工作区时三种操作都会被拒绝。不选任何一项时什么都不动，重启后会再问。
- 手动工作树（「源代码管理」与「设置 · 工作树」）建在同一目录下的 `manual-<分支名>`，可打开为工作区；不能移除主工作区、当前打开的工作区或旨意仍在使用的工作树，有未提交改动时需要强制移除。

## 命令改动快照
- 会改动文件的 `run_command`（只看不改的命令除外）前后各对工作区做一次快照，差异记为该节点的改动，可以撤回（设置 `commandSnapshots`，默认开）。快照仓库在 `<数据目录>/snapshots/<工作区路径哈希>/`，是 Edict 自己的 git 仓库（`GIT_DIR` 指向它、`GIT_WORK_TREE` 指向工作区），**不碰工作区自己的 `.git`**，不是 git 仓库的文件夹也能用。
- 快照仓库里存有工作区文件内容的副本；不进快照的有：工作区 `.gitignore` 忽略的文件、依赖 / 缓存 / 构建目录、`.env*`、`*.pem`、`*.key`、`*.p12`、`*.keystore`、`id_rsa`、`credentials`。记下的改动前后内容存入 `blobs/`。
- 上限：单个文件 2 MB（更大的只记文件名，不能撤回）；每个工作区 2 万个文件、快照仓库 512 MB（超过 80% 时 gc，gc 后仍超限则对该工作区停用）；每条命令最多记 500 处改动、64 MB 内容。快照出错只写审计，不影响命令本身。
- 撤回单个节点或整道旨意时从最新的改动倒序进行；文件在改动之后又被改过时整体不执行并列出冲突文件，由你确认后才强制撤回；不会写到旨意所在工作区之外。

## 语言服务（LSP）
- Edict **不安装**语言服务器：只在本机查找已安装的可执行文件（`PATH` 加常见安装目录，如 Homebrew、`~/.cargo/bin`、`~/go/bin`、nvm、pnpm、`~/.local/bin`；macOS 上另用 `xcrun --find`），不经 shell；检测时可能运行该程序的 `--version`。找不到时「设置 · 语言服务」和 `lsp` 工具只给出安装命令，由你自己复制执行。你也可以为某个服务器指定自定义路径（存于 `lsp.json`）。
- 按需启动：编辑器打开该语言的文件、或 Agent 调用 `lsp` 工具时，每个（项目根 × 服务器）启动一个子进程，经 stdio 通信。进程以你的用户身份运行，`cwd` 为项目根（工作区根，或工作区内最近的带项目标记的目录；旨意工作树有自己的进程），环境同命令执行（剔除名称含 KEY/TOKEN/SECRET/PASSWORD/CREDENTIAL 的变量）。闲置 10 分钟停止；崩溃后退避重启，5 分钟内崩溃超过 3 次就不再自动重启。
- 客户端只读：文档内容一律从磁盘同步；服务器发起的编辑（`workspace/applyEdit`）与打开文档请求一律拒绝；路径经工作区边界校验，工作区外的结果单独标注。`lsp` 是只读工具，所有权限模式都可用。
- 语言服务器是你自己安装的第三方程序，Edict 不限制它自身的文件与网络访问。

## 编辑器接入（ACP）
- 默认关闭。在「设置 · 编辑器接入」开启后（`acpEnabled`），Edict 在 `<数据目录>/acp.sock` 监听一个 Unix 域套接字：绑定时即为 `0600`，只有运行 Edict 的同一系统用户能连接；所在目录不存在时以 `0700` 创建。关闭 ACP 或退出 Edict 时删除。路径上已有非套接字文件、或另一个进程正在监听时拒绝启动。最多 8 个连接，连上后 15 秒内不发 `initialize` 即断开。
- 编辑器启动的是 Edict 自带的 `acp-bridge.js`（用 Edict 自身的可执行文件加 `ELECTRON_RUN_AS_NODE=1` 运行），它只把 stdin/stdout 原样转发到套接字，不解析协议、不持有凭据；在 macOS 上连不上时用 `open -b app.edict.mac` 启动 Edict 并最多等 20 秒（`--no-launch` 可关闭）。
- **逐个编辑器批准**：新编辑器第一次连接时弹原生对话框（默认按钮是「拒绝」）。批准按编辑器自报的名称记住，只在本次运行期间有效；关闭 ACP 或退出 Edict 后清空。
- 编辑器**能做**：新建 / 恢复会话；发送提示（与在 Edict 里下旨走同一个入口，包括 `@mcp:` 引用的展开）；切换 Solo / Court Lite / Full Court；取消；接收进度、方案和改动 diff；对该旨意待批的操作（含写任务开工）选择准许或驳回。编辑器里的「本会话始终允许」只在这个 ACP 会话内有效，不会写进 Edict 的允许规则，也从不覆盖高风险操作。
- 编辑器**不能做**：方案御览、御批结案、预算等关卡只能在 Edict 里处理（ACP 这一轮到此结束）；高风险操作默认只能在 Edict 里确认（`acpHighRiskInEdictOnly`，默认开；关闭后编辑器对高风险操作也只能逐次允许）；编辑器提供的 MCP 服务不会启动；图片和音频附件被忽略；编辑器的工作目录与 Edict 当前工作区不同时，必须由你在原生对话框里同意切换（有旨意正在主工作区执行时直接拒绝）。Edict 不调用编辑器的文件或终端接口，读写都在 Edict 自己的工作区边界内进行。
- 会话索引存于 `acp-sessions.json`（含提示原文；最多 200 个会话、每个 100 轮）。审计记录 `acp_session_new` / `acp_session_load` / `acp_workspace_switch`，编辑器做出的审批以 `acp:<编辑器名>` 记为操作者。

## 数据存放（本地存储不是安全沙箱）
`~/Library/Application Support/Edict/EdictData/`：
- `edict.db`（SQLite，WAL 模式，旁边会有 `edict.db-wal` / `edict.db-shm`）：任务、议政、会话、奏折、朱批、要闻、统计、设置与模型服务（**不含 Key**），包括典章与「本工作区永久允许」规则
- 从 1.x 升级：首次启动 2.0 时 `state.json` 与 `settings.json` 在一次事务中导入 `edict.db`，原件复制到 `backup-1.x-<日期-时间>/`（附回滚说明 `README.txt`），数据目录里的原件改名为 `*.json.migrated`，旧版不会再读到它们；之后若又出现 `state.json`（例如再用 1.x 打开过），2.0 不读取它，只记一条日志。`edict.db` 损坏时改名为 `edict.db.corrupt-<时间>` 留作诊断，有 1.x 备份时从最新的备份重新导入
- `backups/edict-<日期-时间>.db`：「设置 · 存储与备份」中「立即备份」生成的完整副本（`VACUUM INTO`），和 `edict.db` 一样不加密
- `secrets.json` API Key、MCP 配置中的密钥（`mcp:…`）与 MCP OAuth 令牌和客户端注册（`mcp-oauth:<服务名>`）：Electron `safeStorage`（macOS 钥匙串派生密钥）加密后 base64；若系统不支持加密会在「模型服务」与「存储与备份」中明示
- `mcp.json`（MCP 服务，不含密钥与令牌）· `mcp-policy.json`（工具策略、授权、已信任命令哈希）
- `audit.jsonl` 哈希链审计；`activity/*.jsonl` 活动流；`blobs/` 文件改动前后快照（含命令改动）、MCP 返回的图片 / 二进制资源与超长资源全文（内容寻址）；`skills/*/SKILL.md`；`designs/` 协同设计
- `snapshots/` 命令改动快照仓库（含工作区文件副本）· `worktrees/` 旨意工作树与手动工作树
- `lsp.json` 语言服务开关与自定义路径 · `acp-sessions.json` 编辑器会话索引 · `acp.sock`（仅 ACP 开启时存在）

任何能读取你用户目录的进程都能读取这些文件，包括备份、快照仓库和工作树（Key 除外，需钥匙串解密）。数据库与备份里有旨意原文、方案、对话与回奏。

## 联网抓取与搜索（2.1）
- `web_fetch` 默认开（「设置 · 联网与搜索」可改为每次询问或关闭）。只抓公网 http(s)：域名解析后再判断，回环、内网、链路本地地址（含 IPv4 映射的 IPv6）一律拒绝；每一跳重定向都重新检查，最多 5 跳；单页最多 2 MB、20 秒，转成纯文本后最多 2 万字。
- `web_search` 走你在设置里配的搜索服务，或模型服务自带的联网搜索。搜索服务的 Key 存钥匙串，不进设置、审计和日志。没配置时官员上疏请旨，由你配置、只用抓取或驳回；每道旨意只问一次。

## 命令沙箱（2.1）
- macOS 上，官员的 `run_command` 在 `sandbox-exec` 里执行。规则只在默认允许之上加拒绝项：只能写工作区（或旨意工作树及其 git 目录）、临时目录和包管理器缓存；放密钥、令牌、浏览器数据的目录（如 `~/.ssh`、`~/.aws`、钥匙串、浏览器配置）和 Edict 自己的数据目录不能读（数据目录里的旨意工作树除外）；联网默认开，可在「权限与审批 · 命令沙箱」关掉。
- 命令被拦下时弹卡片：不用沙箱重跑这一次 / 让本工作区可写这个目录 / 作罢。发版、部署命令本来每次都要确认，不进沙箱。沙箱不改变审批规则：高风险命令照样逐次确认。

## 外部智能体（客卿，2.1）
- 客卿是你本机已经装好、支持 ACP 的编程智能体。Edict 只启动名册里的命令（内置几种的自动检测，或你自己填写的），不替你安装或登录；进程以你的用户身份运行，环境同命令执行（剔除含 KEY/TOKEN/SECRET/PASSWORD/CREDENTIAL 的变量），工作目录是旨意自己的工作树。没有工作树（不是 git 仓库）时不用客卿，退回本部官员。
- 客卿通过 ACP 请求读写文件、开终端时，走 Edict 自己的工具：路径边界、权限模式、审批卡、命令沙箱、改动记录都和官员一样；它的权限请求转成 Edict 的审批卡，同一操作不重复问。
- **客卿用自带工具做的事不经过 Edict。** 它直接改的文件，Edict 在它办完后对工作树做影子快照比对，记为「客卿改动」，可以撤回；只读子任务里有这种改动时弹卡片问保留还是撤回（全自动模式先保留并提示）。它自己发起的网络请求（访问它的模型服务等）由它自己决定，费用记在它的账号上。客卿自带的权限设置照它自己的规则生效。
- 测试连接只在一个空的临时文件夹里启动、握手、开会话再关掉，不让它干活。

## 定时旨意与排班（2.1）
- 定时旨意到点直接下旨（不经太子分拣），在排定时选的文件夹里办，权限在排定时定好：只读（写子任务改为只读执行、不跑命令）/ 每次改动都问 / 在旨意工作树里改（只在自己的工作树里免询问写入与执行；高风险操作和有外部影响的 MCP 工具仍问；不是 git 仓库或 Solo 时退回每次都问）。结案合并仍由你决定。
- 排班的每一路在自己的工作树和分支里办，从旨意工作树当时的状态（用临时索引文件做的快照提交，不动 HEAD 和索引）出发；选中的一路把改动复制进旨意工作树，旨意里也改过的文件做三方合并，冲突处保留旨意的版本并列出。落选的各路工作树删除，分支按你的选择保留或删除；取消旨意时一并清掉。
- 工作树准备脚本在新工作树里、以你的身份执行，有时限，环境同命令执行，另加 `EDICT_PORT` 等变量；它不在命令沙箱里运行，内容由你在设置里填写。

## 外发请求范围
仅以下几类，且都由你配置或主动触发：
1. 「设置 · 模型服务」中填写的模型服务 base_url；
2. 「天下要闻」中你添加的 RSS/Atom 地址（点「采集」时）；
3. 「设置 · 技能」中你粘贴的远程 SKILL.md（仅 https），以及你点「检查更新」或「更新」时再次请求同一链接；内置技能包随应用发布，不联网；
4. 你在 `mcp.json` 中配置的远程 MCP 服务地址，以及你批准运行的本地 MCP 程序自身发起的请求（由该程序决定）；
   远程服务要求登录时，该服务声明的授权服务器（元数据发现、动态注册、换取令牌——仅在你点「登录」后；此后续期与退出时的令牌吊销）。授权页在你的系统浏览器中打开；
5. 仅当你在预览栏允许外部网络时，被预览页面引用的外部资源；
6. Agent 执行的命令、你安装的语言服务器自身发起的请求（由该程序决定）。
7. 官员的 `web_fetch` 抓取的公网网页（见上文限制），以及你配置的搜索服务；
8. 你启用的外部智能体（客卿）自身发起的请求（由该程序决定）。网络外发类命令（curl、wget、ssh 等）与安装依赖属高风险，逐次确认；发版 / 部署命令逐次确认，除非你为该工作区开启了永久允许。

语言服务、编辑器接入（ACP）、旨意工作树与命令快照本身不发起外部请求：ACP 只用本机套接字，工作树与快照只运行本地 git 命令（不 fetch / pull / push）。应用本身不包含遥测、更新检查或任何预置外部地址。API Key 只作为请求头发往对应 base_url，不写入日志、审计、活动流、导出或测试夹具（测试中有断言检查）。
